# Stella

Desktop app that draws cards, boards, tokens, dice and the other components of a game from a spreadsheet. It works on local files, on Mac, Windows and Linux. Interface in English and Italian.

A project is a folder with the templates, an Excel file with one sheet per set and the images. Stella draws every card from the data, exports PDFs for printing and ready-made Tabletop Simulator objects (decks, tokens, tiles, boards and dice), and writes the rulebook with the real cards inside.

The presentation site, with downloads and tutorials, is <https://stella.lucadj.eu/>. The user guide is in [docs/guide](docs/guide/README.md) (Italian: [docs/guida](docs/guida/README.md)).

## Installation

Step by step, with the macOS and Windows warnings: [Installing Stella](docs/guide/README.md#installing-stella) in the user guide.

Packages are on the [Releases](https://github.com/lucadj77/stella/releases) page or, for a build not yet released, among the artifacts of the **Build** action in [Actions](https://github.com/lucadj77/stella/actions/workflows/build.yml).

- **Mac**: `Stella-<version>-mac-arm64.dmg` for Macs with an Apple chip (M1 and later), `-mac-x64.dmg` for those with an Intel processor. Open the .dmg and drag Stella to Applications. The app is not signed with an Apple certificate, so on first launch macOS says it cannot verify it: close the warning, open **System Settings → Privacy & Security** and press **Open Anyway** at the bottom. Alternatively, from Terminal: `xattr -dr com.apple.quarantine /Applications/Stella.app`. Only needed the first time.
- **Windows**: `Stella-<version>-windows-setup.exe`. Without a signature, Windows SmartScreen shows "Windows protected your PC": press **More info** and then **Run anyway**. For the portable version, which does not install, there is `Stella-<version>-windows-portable.exe`: it starts directly, also from a USB stick, and keeps its data (recent projects, preferences) in the `Stella data` folder next to the file.
- **Linux**: `Stella-<version>-linux-x86_64.AppImage`, to be made executable (`chmod +x`) and started, or `Stella-<version>-linux-amd64.deb` for Debian and Ubuntu (for example `sudo apt install ./Stella-1.0.0-linux-amd64.deb`). The AppImage needs libfuse2 (on Ubuntu `sudo apt install libfuse2t64`). Both also come as `arm64` for ARM computers, including ARM Chromebooks through their Linux environment.

Where nothing can be installed there is the **web version**, for Chrome, Edge or Opera (in Brave enable `brave://flags/#file-system-access-api`): <https://stella.lucadj.eu/app/>. It works on the same projects, with a few features less; see [docs/web.md](docs/web.md) (in Italian).

## AI-assisted development

Stella is designed, directed and tested by me, Luca Di Gialleonardo, on my own board game prototypes. A large part of the code was written with an AI coding assistant (Claude Code): you can see it in the commit history, where those commits carry a `Co-Authored-By: Claude` line.

There is no AI inside the app:

- Stella doesn't generate images, text or anything else for you, and has no AI features.
- Your art, your text and your data stay yours and stay on your computer. The app sends none of your data to any server: it only connects to the internet to check for updates and, when you open them, to browse Google Fonts and Iconify icons, or to read a Google sheet you link.

The only AI-related part is optional. A project is just files on your disk, so you can let an AI agent you already use (ChatGPT, Codex, Claude Code…) work on it. To help with that, Stella has a command-line tool and a skill file (`skill/stella/SKILL.md`) that explain the project format to the agent.

- The skill is not part of the app: the exe, AppImage and dmg contain no skill file and no skill text.
- The optional **AI tools** window downloads the skill from GitHub (the version matching your installed app) only when you press the button to copy it or save it for your agent. If you never do, nothing AI-related is installed, runs or is sent anywhere.
- The `stella` command-line tool stays in the app: it isn't AI, it lets you run the same operations from a terminal or a script, and it's also what agents use.
- Deleting `skill/stella/SKILL.md` from the sources doesn't affect the app or the build.

## Development

```bash
npm install
npm run dev     # starts the app
npm test        # tests
```

To try it, press **Open the example project** in the start screen (the project is generated by `scripts/guide/crea-progetto-esempio.mjs` into `resources/examples`). The `stella` command and the skill for AI agents are described in [docs/cli.en.md](docs/cli.en.md). The project format is described in [docs/format.md](docs/format.md).

Requirements are in [docs/requisiti.md](docs/requisiti.md) and the functional specification in [docs/specifica.md](docs/specifica.md), both in Italian. The site source is in [site/](site/LEGGIMI.md).

## Build

```bash
npm run build:mac    # or build:win, build:linux; packages go to dist/
```

Each system builds its own packages well (the .dmg needs a Mac, the Windows installer needs Windows or Wine). To get them all at once there is the **Build** GitHub action: start it by hand from Actions, or create a tag (`git tag v1.0.0 && git push origin v1.0.0`) and the packages end up in a public release, downloadable by anyone without a GitHub account. The version is the one in `package.json` and the news is in [CHANGELOG.md](CHANGELOG.md): the full procedure is in [docs/rilascio.md](docs/rilascio.md) (in Italian).

## Stack

Electron, React and TypeScript with electron-vite. Electron was chosen over Tauri because it bundles Chromium and guarantees the same rendering of cards and PDFs on every operating system.
